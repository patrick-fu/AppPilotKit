# ADR 0009: Private Broker bootstrap and Target transport

- Status: Accepted
- Date: 2026-08-30
- Accepted: 2026-08-31 (evidence mode; task `01a05520-4b7b-7821-b25c-7f4f3d20db40`)
- Issue: [#62](https://github.com/patrick-fu/AppPilotKit/issues/62)

## Context and decision

Issue #62 must connect the installed `apppilotkit` binary to real opted-in iOS Simulator and Android Emulator Targets without changing CLI v1, Protocol v1.2, or either production SDK public interface. ADR 0007 fixed the ownership and trust boundaries but intentionally left the private bootstrap, framing, cryptography, deadlines, and lifecycle unspecified. We therefore keep the existing two-entry `CatalogRuntime` as the CLI production seam, add a private `BrokerCatalogRuntime` adapter behind the installed binary, and put lifecycle, private IPC, lease routing, bootstrap, Noise state, and exact cleanup in a current-user Session Broker. The byte-level contract and vectors under `transport/contracts/v1` are the implementation source of truth.

The package layout is fixed. `<prefix>/bin/apppilotkit` remains the only public product executable. `<prefix>/libexec/apppilotkit-broker` is a private, on-demand, current-user sidecar. `<prefix>/libexec/apppilotkit-target-prepare` is a setup-only private executable: it receives an exact non-secret device/app selection on stdin and asks the Broker to prepare the exact `PrepareKey = (platform, device_selector, app_id, artifact_encoding, SHA-256(exact encoded app artifact bytes))`. `artifact_encoding` is platform-fixed to `ios-app-tree-v1` for iOS Simulator and `raw-file-v1` for Android Emulator. With no eligible Broker-owned lease it launches the selected #62 Target and completes authenticated process bootstrap. With an exact eligible live lease it only mints a fresh Ready Target Reference: it does not launch, activate, replace PBS, repeat NK, or open a Protocol Session. A conflicting build, Process Generation, Listener Epoch, endpoint, ownership, expiry, or heartbeat fails closed. The iOS #62 path never attaches an arbitrary running Target. Prepare never invokes `semantic.list`, renders a CLI Machine Result, or substitutes for the installed CLI verdict.

The operator flow is exactly:

1. `"<prefix>/libexec/apppilotkit-target-prepare" "--request-fd=0" "--output=json"`
2. `"<prefix>/bin/apppilotkit" "catalog" "list" "--target=<opaque>" "--output=json" "--non-interactive"`
3. A complete non-empty list projects the Target-issued session only through an existing `catalog.show` Next Action: `"<prefix>/bin/apppilotkit" "catalog" "show" "--capability" "<exact-id>" "--declaration-revision" "<exact-revision>" "--session=<target-issued-id>" "--target=<same-ref>" "--output" "json" "--non-interactive"`. A truncated list projects `"<prefix>/bin/apppilotkit" "catalog" "list" "--session=<target-issued-id>" "--target=<same-ref>" "--cursor" "<opaque-cursor>" "--output" "json" "--non-interactive"`. A complete empty list projects `"<prefix>/bin/apppilotkit" "catalog" "list" "--session=<target-issued-id>" "--target=<same-ref>" "--output" "json" "--non-interactive"` as the existing safe selector carrier.

The first verdict invocation contains no `--session`. CLI v1 keeps its existing broad opaque `--target` syntax parser; the private adapter validates local grammar before IPC, while the authenticated Broker performs the exact live-lease lookup before platform effects. `BrokerCatalogRuntime.select()` constructs the exact `session.open` JSON-RPC bytes and sends those bytes plus their digest in private IPC. The Broker atomically redeems the fresh reference, opens a fresh authenticated transport connection, and forwards the bytes opaquely. Its private result returns opaque Target response bytes, digest, transport generation/epoch, and Handoff state—not parsed Protocol fields. The adapter validates the digest, JSON-RPC response, Target-issued id, generation, negotiated version/capabilities/limits, and only then returns `OpenedProtocolSession`. Match-only commands may reuse a consumed reference only with its already-bound session; a different or new session always requires a fresh prepare reference. No selector means the existing selection-required failure. One available Target never authorizes automatic selection. Platform locators such as UDID, serial, bundle id, or package id are not Target references.

Two evidence applications are authorized solely to break the #62/#63 dependency cycle: `ios/TransportSmokeHost/**` and `android/transport-smoke-host/**`. Each Debug/Internal app registers exactly one fixed read-only Resource, `smoke.ready`, declaration revision `1`, output schema `schema_smoke_ready_v1`, and value `{"ready":true}`. They contain no Action, mutation, reset, restart, shared harness, scenario system, DemoCatalog, Journey 7, fixture handler, or canned trace. #63 must not import, copy, or turn their sources into its shared Acceptance Host foundation.

Target transport is an independent internal integration. Future Swift and Kotlin wrappers call the same publish-disabled Rust Noise core through a narrow C ABI/JNI boundary; Host, iOS, and Android do not implement separate cryptography. Only the two #62 Smoke Hosts and future Acceptance Hosts explicitly link this integration. The existing iOS package products, Android production modules, public symbols, and production SDK interfaces remain unchanged. Release/Production Targets have no build edge, manifest entry, listener, bootstrap path, Noise symbol/string, or runtime socket from this transport.

## Canonical domain terms

- **Ready Target Reference**: an opaque, non-secret, single-Target Broker locator returned after a new bootstrap or exact eligible owned-lease reuse. Its child state is `Minted -> Redeeming -> Consumed | Expired`. It is memory-only, bound to one Target Lease, Process Generation, and Listener Epoch, and permits exactly one target-only `session.open` redemption before its 30-second deadline. Match-only use is valid only with the already-bound Target-issued Session; every new Session requires a fresh prepare reference.
- **Target Lease**: the Broker-owned, memory-only lifetime and cleanup ledger for exactly one selected Target process and Listener Epoch. Idle TTL is 120 seconds and absolute TTL is 900 seconds.
- **Process Generation**: a random integer in `1..=9007199254740991` created by the Target for one app process, preserving exact JSON integer interoperability. Process restart always changes it and invalidates every prior reference, secret, and session.
- **Listener Epoch**: an integer in `1..=9007199254740991` scoped to one Process Generation. Eligibility loss increments it before listener/session invalidation; an old epoch never rebinds. Exhaustion is terminal `internalError`, never wraparound.
- **Process Bootstrap Secret (PBS)**: the 32-byte secret delivered inside Noise NK message 2. It is memory-only, lease-scoped, and used only as `psk0` for fresh per-session Noise handshakes. It is never an action credential or direct session key.
- **Opened Protocol Session**: the Target-issued `session.open` context containing session id, process generation, negotiated Protocol v1.2 capabilities, and limits after transport authentication and Finished exchange.
- **Transport Handoff Boundary**: the exact instant a complete authenticated opaque application plaintext passes framing, sequence, binding, lifecycle, and byte caps and is handed to the existing Target runtime. Transport does not decode UTF-8, JSON-RPC, envelopes, methods, or parameters.
- **Mutation Dispatch Boundary**: the existing `TargetActionCoordinator` claim/handler handoff after policy, authorization, evidence-before, liveness, and Single-Writer acquisition. Only the coordinator observes it.
- **Stale Terminal State**: the irreversible per-lease or per-session state entered after generation/epoch mismatch, eligibility loss, TTL, Broker loss, endpoint/authentication failure, or cleanup failure. Stale state rejects all new work and never restores, retries, or rebinds.

## Security and lifecycle decision

For iOS, `.app` identity is SHA-256 of the complete `ios-app-tree-v1` stream defined under `transport/contracts/v1`, not a directory pathname, archive metadata, or a per-file digest manifest. Its domain-separated magic/version, entry count, strict raw UTF-8 byte ordering, record kind/path/execute-class/file length/exact bytes, complete directory-parent topology, path and size limits, prohibited link/special/ResourceFork types, metadata exclusions, and bundle `Info.plist`/root executable checks are wire-level commitments. Code signatures and `Info.plist` participate as ordinary exact file bytes; Unicode normalization and case folding are forbidden. Construction and hashing are streaming.

Prepare copies an accepted iOS tree into a Broker-owned private snapshot without ordinary xattrs or ACLs and preserves only directory/file topology, exact file bytes, and the one-bit execute class. It rejects instability or a prohibited type before install, derives the canonical stream from the completed snapshot, installs that exact snapshot on the selected UDID, and launches the exact validated App id while terminating any older instance. The lease records only the PID returned for that launch and never adopts an arbitrary or ambiguous running process; PID change invalidates ownership. These are contract obligations for D3. This D0 checkpoint does not claim a libproc attribution implementation or a completed real Simulator journey.

Process bootstrap uses Noise revision 34 `Noise_NK_25519_ChaChaPoly_SHA256`: Target is initiator; Broker is responder with a fresh one-time static X25519 keypair whose public key is non-secret launch material. The initial non-secret launch descriptor carries `SHA-256(UTF8(full initial Ready Target Reference))`; that digest is only the bootstrap anchor. Encrypted message 2 carries the PBS. The Target then sends an encrypted acknowledgement binding the exact Target Lease, Process Generation, and Listener Epoch. One bootstrap may authorize multiple independent child Sessions. Each uses a fresh connection, fresh ephemeral keys, fresh Target-issued session id, independent limits/idle state/runtime instance, and `Noise_NNpsk0_25519_ChaChaPoly_SHA256` with PBS as `psk0`. Per-session prologue and Finished bind lease, generation, epoch, hard limits, and NK handshake hash; they contain neither Ready Reference digest nor agent binding. The implementation uses Noise split keys and sequence handling directly; it adds no KDF, HMAC, rekey, or custom nonce schedule.

Each authenticated connection owns one existing `SemanticProtocolRuntime`/`ProtocolRuntime` instance. Instances share only the immutable Semantic Catalog and the existing `TargetActionCoordinator`. Closing, idle-expiring, or authentication-failing Session A destroys only A. Lease/process/epoch/Broker-heartbeat loss atomically stales all child references and Sessions and invalidates every live runtime instance. Read exchanges may run concurrently; only the coordinator serializes mutations. There is no global per-Target runtime invalidation for a single-session failure.

The defended boundary rejects other OS users at Broker IPC, unrelated Android app processes, wrong roles, modification, replay, cross-target/lease/generation/epoch use, endpoint mix-up, stale state, secret placement in product-controlled observable surfaces, LAN discovery/listeners, fixed global ports, and mDNS. Android peer UID is defense-in-depth only and never Host identity. The trust anchor for Target identity is the Broker's exact platform launch plus exact endpoint/stream and generation/epoch binding, not a Target long-term key.

The residual boundary explicitly does not defend root, kernel, hypervisor, a compromised same-current-user process, any same-current-user process that obtains the public launch descriptor and wins its endpoint race, debugger/ptrace, swap/hibernation/crash dumps, compromised CoreSimulator/ADB/adbd/usbmux/platform tooling, another authorized ADB Host racing bootstrap, or malicious replacement of a non-secret launch descriptor. Requiring defense against those actors needs an external trust or pairing decision and is outside #62.

A connection failure records only `NotHandedOff` or `HandoffPossibleOrConfirmed`. Pre-send and provably partial request emission are `NotHandedOff`; a full request without a complete authenticated response is conservatively `HandoffPossibleOrConfirmed`. Read failures map to existing `sessionExpired`, exit 4. A mutating full request without a complete response maps through the trusted CLI side-effect stamp to `action.outcomeUnknown`, exit 5, `retryable:false`, with no replay. There is no runtime-ack record, and Broker/transport never claims Mutation Dispatch or directly emits public errors.

Authenticated transport `malformed` and `sequenceViolation` failures map to the existing `sessionExpired`, exit 4, like `oversize` and `recordLimit`; transport never synthesizes application-layer JSON-RPC `parseError` or `invalidRequest`. This pre-handoff mapping does not override the conservative post-handoff mutation ambiguity rule.

Lease-terminal failure rejects new work, cancels control and Target I/O, closes every child stream, destroys keys, closes Target listeners/connections/challenges, invalidates all live runtime instances, advances Listener Epoch only for eligibility loss, cleans only adapter-owned resources, destroys bootstrap material, and releases the lease. Cleanup failure remains failed and stale. There is no automatic retry, restore, rebind, or unknown-process termination. The sole Android pre-bootstrap exception is a confirmed `am start` followed by a failed listener/forward/connect setup: within an independent two-second cleanup deadline, the adapter force-stops only that exact selected package and removes only its exact mapping.

## Rejected alternatives and scope boundary

We reject caller-chosen session ids; implicit or unique-candidate auto-selection; raw platform locators as `--target`; `catalog list` launching/relaunching a Target; arbitrary process attach; Ready Reference as Target authentication input; agent binding as authenticated identity; transport JSON/JSON-RPC parsing; a runtime-ack control record; secrets in argv, environment variables, Activity extras, preferences, Keychain, disk, logs, diagnostics, Machine Results, Next Actions, or Artifacts; fixture/private handlers as real acceptance; promoting #38 probe framing; per-platform crypto; unauthenticated DH; custom KDF/HMAC/rekey; changes to Protocol v1.2, CLI v1 schemas/commands/errors/registry or `CatalogRuntime` interface; production SDK public APIs; and importing #63, #54, or #55 behavior. A future implementation may narrowly change `catalog.rs` guidance projection and its tests for the three existing Next Action forms above; that compatible dynamic content is not a D0 production change.

Golden-vector and local contract evidence are implementation checkpoints only. They do not prove either real Smoke Host journey and do not close #62. Real acceptance requires the same packaged installed binary to complete the public `catalog list` path against actual opted-in iOS Simulator and Android Emulator Targets, with the evidence schema in this contract and without the old ignored Android probe.

Retained installed-journey evidence is closed over both public contracts and transport identity. The reference verifier loads the frozen CLI v1 schemas directly from this repository with external retrieval disabled, but accepts only the exact sorted six-schema inventory and byte hashes pinned in `dependencies.lock.json` before parsing or registration. It validates the complete Machine Result and the `catalog list` data definition, and requires its CLI version to match the installed binary identity. Each primary and concurrent Session record binds its own session digest into independent request, response, and runtime facts; runtime identity and both exchange digests must differ across the two Sessions, and the primary record must exactly equal one concurrent record. The contract reverse inventory excludes only its self-referential root manifest, so files placed under names such as `build` or `reference/target` are not silently non-normative; reference builds must use an external Cargo target directory.

The verifier accepts a raw retained bundle only through `verify --evidence <path>`, rejects duplicate JSON object members recursively before schema validation, and then applies the same semantic evidence checks. Its Smoke Host build scan is bound byte-for-byte and by App id/build/platform-fixed encoding/digest to the launched evidence App artifact. For iOS, both fields contain the complete canonical `ios-app-tree-v1` stream. Production and Release scans each carry a configuration-specific explicit App/build/encoding/digest identity, must differ from the Smoke Host artifact, and may equal each other; a decoy, exchanged, missing, zero-byte, malformed, or Smoke-rebranded capture fails.
